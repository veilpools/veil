# Veil Protocol Implementation Plan (End-to-End)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Veil — the complete zero-knowledge privacy layer for Uniswap v4 on Robinhood Chain, featuring Swap-to-Shield, Shielded Swap, ZK-Gated & Protocol Fee Hooks, client-side note cryptography, and public transparency pages (/contracts, /burn).

**Architecture:** 
- Smart contracts: Solidity 0.8.26/0.8.28 with Uniswap v4 hook system and 0xbow privacy pool core.
- Periphery: `VeilShieldRouter` coordinating PoolManager unlock callbacks, token swaps, and atomic privacy pool deposits/withdrawals.
- Hook: `VeilHook` implementing `beforeSwap` for ZK attestation gating (`VeilAttestationRegistry`) and fee accrual into `VeilTreasury`.
- Client & Web: Next.js 16 + React 19 + Viem + Tailwind CSS v4, containing non-custodial note creation (WASM/BIP-39/PBKDF2+AES-GCM), live contract reads, and swap terminal.

**Tech Stack:** Solidity (0.8.26/0.8.28), Uniswap v4 Core & Periphery, 0xbow Privacy Pools Core v1.2.1, Viem 2.x, Next.js 16, React 19, Vitest, TypeScript.

## Global Constraints
- **Chain:** Robinhood Chain (Testnet 46630, Mainnet 4663)
- **PoolManager Canonical Address (Mainnet):** `0x8366a39CC670B4001A1121B8F6A443A643e40951`
- **Permit2 Canonical Address:** `0x000000000022D473030F116dDEE9F6B43aC78BA3`
- **WETH Canonical Address:** `0x0Bd7D308f8E1639FAb988df18A8011f41EAcAD73`
- **Router Invariant:** Router balance is always 0 at the end of each transaction (zero held custody).
- **Withdraw Security:** Withdrawals can never be blocked or frozen by the guardian or team. The guardian may only pause deposits.
